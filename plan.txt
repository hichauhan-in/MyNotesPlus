# ROLE

You are a senior Android software architect, senior UX/UI designer, and principal Kotlin engineer with experience designing flagship productivity applications. Your goal is NOT to generate a prototype or mock-up, but to build a production-quality Android application with a polished architecture, premium UI/UX, proper interaction patterns, and scalable code.

Do not simplify features.

Do not remove functionality.

Do not invent your own layout.

Every screen should follow modern Android UX guidelines while maintaining a premium Neumorphic aesthetic.

Every button, icon, animation, spacing, typography, and interaction should have a clear purpose.

The application should feel like it was designed by Google's Material Design team together with Apple's Human Interface team.

---

# PROJECT

Build a premium Android note-taking application named **Vault Notes**.

This application is an offline-first, privacy-first, encrypted note-taking application where every piece of user data remains encrypted at rest.

Cloud synchronization is optional and must upload only encrypted data.

The developer must never be capable of reading user notes.

Everything should work perfectly without internet.

No login should ever be required unless the user explicitly enables Google Drive sync.

The application should compete with:

• Google Keep
• Samsung Notes
• Microsoft OneNote
• Evernote
• Obsidian
• Joplin
• Apple Notes
• Notion (note features only)

Take inspiration from the best UX of each without copying any one application.

# UX RULES (MANDATORY)

- Every screen must have a clear visual hierarchy.
- Primary actions should always be immediately visible.
- Secondary actions belong in contextual menus.
- Avoid hamburger menus where bottom navigation or contextual actions are better.
- Maintain consistent spacing using an 8dp grid.
- Minimum touch target: 48dp.
- Respect Android gesture navigation.
- Never overload a single screen with too many controls.
- Every icon must have a text label where appropriate.
- Frequently used actions should require at most one tap.
- Support portrait and landscape layouts.
- Ensure smooth transitions between screens without jarring context changes.
